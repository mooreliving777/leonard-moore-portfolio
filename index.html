02 / ENGINEERING CASE STUDY

The challenge isn’t just writing code.

It’s defining behavior, containing risk, and proving the system does what the business expects.

From a sales lead to a recorded payment

Problem — A service business needs a traceable path from winning a lead through completing work and tracking revenue.

Solution — Extend an existing Express/SQLite application with protected operations routes, a project/task workflow, invoices, and a full-payment recording step.

Validation — Tests cover authentication, organization boundaries, duplicate/retried requests, currency handling, and UI race conditions. The merged main branch has a successful Node.js GitHub Actions run.

Limitations — The first increment does not offer partial payments, online checkout, reversals, or hosted multi-tenant SaaS billing.

03 / HOW I WORK

AI accelerates iteration.
Judgment stays human.

My approach to AI-assisted development is designed around traceability, verification and explicitly stated limits.

01

Define the behavior

Write down the user journey, business rules, authorization boundaries and failure modes before proposing changes.

02

Question the output

Use AI for options and explanations, then challenge assumptions with code reading, tests and independent checks.

03

Test unhappy paths

Check invalid inputs, cross-organization access, replayed operations and post-logout state—not only a successful click path.

04

Document trade-offs

Explain what the code does today, what it does not do, and what would be necessary before wider deployment.
